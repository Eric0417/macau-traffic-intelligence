# 居民出行工作台執行計劃

日期：2026-11-10。執行分支：`codex/resident-workspace`。

## 目標及授權範圍

將網頁由全屏地圖加覆蓋面板，改為居民日常使用的出行工作台。用戶已要求先列詳細計劃，再直接改進網頁、資訊準確度、觸控操作、巴士與站點模型。原生手機 App 留待之後。

主要流程：打開網頁 → 查看常用或附近資料 → 選路線及候車站 → 查看剩餘站數與停站安排 → 按需要打開地圖。泊車流程：選車種 → 搜尋／按距離排序 → 查看空位、資料時間與位置。桌面列表與地圖並排；手機列表及地圖切換，導航留在內容之外。

## 已確認的不足

| 問題 | 證據 | 處理 |
| --- | --- | --- |
| 站名搜尋承諾與功能不符 | `BusPanel` 只按 routeName 篩選 | 路線搜尋明確標示；載入路線後提供站名搜尋，不假裝已有全澳站點索引 |
| 巴士詳情將車牌與車速放在站點前 | 手機 3 號路線實測 | 站點、下一班車、停站安排優先，車輛詳情摺疊 |
| 暫停站同時顯示即將進站 | 官方兩個切片可能不同步，UI 沒有優先次序 | 暫停服務優先，不作可上車承諾 |
| 手機面板遮擋路線 | 68dvh 面板與固定地圖 padding 不一致 | 移除拖動面板；手機列表／地圖模式；地圖尺寸用 ResizeObserver 更新 |
| 桌面、手機各掛載一份面板 | `TrafficDashboard` 重複 render panel | 單一面板掛載，保留清晰的操作狀態 |
| 頁面切換保留不相關捲動位置 | 實測由巴士切去泊車，搜尋欄消失在上方 | 每次切換頁面重設該內容容器位置 |
| 泊車只按私家車空位排序，截斷 80 項 | `ParkingPanel` | 提供官方所有車種、完整結果、距離／空位排序，未知值保留 |
| 查詢後切去其他頁仍輪詢巴士 | enabled 僅檢查 selectedRoute | 只在巴士、相關 AI 情境及出行關注內容需要時更新 |
| 缺資料被畫成零或沒有警告 | 概覽使用 null 的正常狀態分支 | 區分載入、失敗、過期與正常，提供重試 |
| 口岸等候分鐘為程式將狀態碼轉成固定值 | `estimatedWait()` 回傳 10/30/45/60 | 在未核實官方分鐘欄位前回傳 null，保留官方狀態及來源 |
| 泊車時間解析失敗時填現在時間 | `macauIso()` | 回傳 null，不製造更新時間 |
| 「突發事件」由公告文字關鍵字分類 | notices parser 與舊版 Alerts | 改稱交通公告，標示發布日期與抓取時間；調查新的事件來源 |
| 巴士模型零件及比例粗略 | 現有 Blender／GLB | 按澳巴、新福利官方照片重建低面數模型，合併網格及材料 |
| 巴士站只是一個圓點 | 地圖 bus-stations 圖層 | 按 DSAT 站牌照片建立 3D 站牌，近距離顯示，遠距離保留清晰平面標記 |
| 輕軌站缺乏可辨識外觀 | lrt-stations 圖層 | 加入站台及雨篷示意標記，清楚說明不是建築測繪模型 |

## 資料準確度規則

1. 只有已讀取真實回應、可解析、具來源的資料才進入 adapter。公開 API 只傳 normalized contracts。
2. 抓取成功不等於事件剛發生。分開顯示資料發布／觀測時間與最後取得時間。
3. 不將路況顏色、車速、站數轉成未經驗證的到站分鐘。口岸狀態也不擅自轉成輪候分鐘。
4. 巴士位置仍是官方估算；車款與 busType 沒有核實對照前，只按營運公司選示意模型。
5. 3D 站牌及站台放在官方座標，但造型、朝向、尺寸屬示意。沒有站亭結構資料時不宣稱實景重建。
6. API 失敗保留有效舊資料並標過期。沒有有效資料就顯示無資料。可用模組繼續操作。
7. 收藏留在本機。精確定位只在用戶按「附近」後申請，僅用於瀏覽器內距離計算，不傳給 API／AI。

## 資訊擴充及來源調查

本輪優先將既有欄位完整呈現：SMG 預報與警告、DSAT 各車種空位、停站清單、站點路況、官方車輛估算、各模組來源及更新狀態。不新增推測數字。

交通消息另作來源審核：DSAT、PSP、政府 RSS／GCS、兩巴官方服務消息。每個候選記錄端點、發布時間、最近樣本、可存取性、覆蓋、授權及失效行為。有可靠可解析來源才接入；新聞稿或 RSS 仍稱公告，不能稱為完整即時事故流。需要商業授權的接口只記錄為後續選項，不在本輪購買或聲稱澳門覆蓋。

全澳站點搜尋需要可靠的全網站點索引。目前每條線的官方站序可查，本輪提供線內站名搜尋及收藏。全網索引、跨模式轉乘規劃、推送通知、時序預測都需各自取得資料後再做。

## 交互與視覺

- 主導航：出行、巴士、泊車、更多。更多內有路況總覽、輕軌、交通公告、鏡頭、AI 及來源狀態。
- 出行頁列常用路線／站點及停車場，沒有收藏時提供可操作入口，不填示例即時資料。
- 巴士先選路線，詳情獨立顯示，返回路線目錄有明確按鈕。候車站可從列表或地圖選取，顯示方向終點、站數、停站狀態。
- 手機內容按正常頁面捲動，底部導航獨立；輸入框至少 16px，主要觸控範圍至少 44px。列表與地圖用明確切換控制。
- 預設 2D，3D 由用戶開啟。日間及夜間使用同一組語意色，藍色代表操作，路況保留文字及圖例。
- 尊重 reduced motion；地圖標籤與動態模型按縮放顯示，避免在總覽塞滿模型。

## 技術範圍及檔案

沿用 Next.js 16.3.6／React 19、MapLibre、Three.js、Zod、共享 cache 與現有 `/api/v1`。不改 runtime 架構、不加依賴、不加帳戶系統。

- `src/components/dashboard/traffic-dashboard.tsx`：單一工作台、導航、來源輪詢、定位、偏好。
- `src/components/dashboard/panels.tsx` 與新增出行頁：候車、泊車、資料狀態、天氣預報與來源入口。
- `src/components/dashboard/macau-map.tsx`：站點選取、可用視窗 fit、尺寸更新、2D／3D 模型。
- `src/lib/`：距離、篩選、收藏及狀態的小型純函數；沿用現有 TypeScript 命名方式。
- `src/server/sources/`：僅經核實的欄位修正或新增公告 adapter；測試使用固定 fixtures。
- `scripts/build-transit-models.py`、`docs/models/`、`public/models/`：可重建 Blender 場景、低面數 GLB、預覽及參考來源。
- `tests/`、`e2e/`：資料準確度與主要觸控流程回歸。

程式風格沿用現有例子：`const facilities = (data ?? []).filter(...)`，純函數先有 fixture 測試，不為單一功能增加通用框架。

## 執行順序及驗收

1. 資料修正：先加會失敗的測試，再移除推算口岸分鐘、虛構時間、錯誤的突發消息承諾。更新 DATA_SOURCES 與 ADR。
2. 工作台：單一內容掛載、四入口、列表／地圖、日夜模式、可用來源狀態。先通過型別及單元測試。
3. 候車與泊車：站點先行、停站優先、收藏、車種、完整列表、附近距離；用固定 API fixtures 驗證。
4. 模型：收集官方圖片 → Blender 重建 → 匯出 GLB → 渲染預覽 → 地圖近距離驗證。保留原 `.blend`，新檔版本化。
5. 公告來源：記錄真實結果；接入通過條件的來源，否則保留明確來源連結及限制。
6. 完整驗證：320／390／768／1440px、觸控滑動與點擊、鍵盤、錯誤與過期狀態、模型載入失敗回退、切頁停止巴士輪詢、正式 build。

固定驗證命令：

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
npm run docs:check
```

刻意連官方服務的檢查另用 `npm run verify:sources`，結果記錄在文件；單元及 e2e 不連政府服務。e2e mock 公開 API 和 OpenFreeMap style。

完成條件：上述流程可用，無錯誤的正常／即時承諾；三語可操作；模型來源與示意界線清楚；所有必要檢查通過；執行清單記錄已完成及實際外部限制。本輪不把未核實資料以完成項目交付。

## 交付與限制

交付詳細計劃、可運行的網頁修改、Blender 原始檔與 GLB、模型預覽、來源審核紀錄及測試結果。維持本地可 review 的版本。部署需在完成驗證後另行處理，不把本地變更描述成已上線。
