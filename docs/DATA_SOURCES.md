## Licensing and attribution

- Application code is MIT licensed.
- DSAT, SMG, MLM, FSM, and OpenStreetMap data remain subject to their publishers' terms.
- Parking coordinates use OpenStreetMap (ODbL) and, for 14 car parks, the Macau SAR Government WebMap Carpark POI layer (DSSCU); government GIS data remains subject to its publisher's terms.
- OpenStreetMap-derived LRT geometry requires ODbL attribution.
- Camera streams are played directly from the publisher and are never recorded or re-hosted.
- Assistant answers are generated text from the configured provider. The app attributes the model in the response meta and stores neither questions nor answers.
- The public API exposes normalized live views only, not bulk history or original datasets.

## Adapter notes

- `official-news`: `/api/v1/traffic/news` returns normalized `{ items, feeds }`. The government RSS directory lists both endpoints. On 2026-11-10 direct reads returned valid XML: 33 GCS items and 20 DSAT items. GCS items use `title`, `description`, ISO `pubDate`, `link` and `dc:creator`; DSAT uses RFC-style `pubDate`. GCS titles are filtered for transport terms; DSAT news is retained. Links are restricted to HTTPS and each publisher's own hostname. Summaries are stripped of HTML and capped at 240 characters. Identical titles are deduplicated; publication times remain those of the publishers. These are limited recent-news feeds, not a complete incident feed or proof that an event is still active. Every feed exposes availability; all-feed failure uses the shared stale fallback instead of an invented empty collection. No history is retained.
- `notices`: roadwork dates embedded in a title describe an effective window, not a publication timestamp. Those entries now return `publishedAt: null`. The UI keeps the window in the title and labels the collection as published announcements. The `incident` category is a keyword classification only; it does not establish an ongoing event. Failure of every DSAT page throws so the cache can retain valid older data.

- 2026-11-10 accuracy correction: `borders.estimatedWaitMinutes` remains nullable for compatibility and is now always null. The adapter previously generated 10/30/45/60 minutes from status codes; those values were not read from an official waiting-time field. The UI uses the official qualitative status. A direct request on this date received an HTML challenge, while the adapter verification later returned eight entries. Availability is variable. See `SOURCE_AUDIT_2026-11-10.md`.
- `parking.updatedAt` is now nullable. An absent or invalid publisher timestamp stays null; it is never replaced by the current time. Response metadata still records the server retrieval time separately.
- Client freshness uses elapsed time as well as response timestamps, so a previously fresh response becomes delayed after contact is lost. A catalog's freshness is not used as proof that its vehicle-location slice is current.

- `cameras`: the official catalog repeats some border cameras once per zone under a shared numeric id. The adapter keeps every zoned entry, drops byte-identical repeats, and appends a short deterministic suffix to colliding ids so map features, list keys, and camera selection stay stable.
- `lrt-network`: the server rebuilds the network from OpenStreetMap route relations every 6 hours. Lines are grouped by `ref`; stations are merged by name and proximity under 400 m, so 協和醫院 and 蓮花 stay interchanges. Known stations keep the curated official names and ids from `data/lrt-network.json`; new stations use the OSM name tags. Overpass endpoints are tried in order (`LRT_OVERPASS_URL` overrides them), and failures or a result with fewer than 3 lines or 15 stations fall back to the checked-in file. `npm run build:lrt` refreshes that file with the same builder. The map may show one train per selected line that moves along the OSM-derived alignment as an explicitly labelled schematic animation at a fixed display speed; it is not live data (ADR 0008).
- `roads`: DSAT publishes live levels for 1,268 monitored segments only. The map draws the full OpenStreetMap street network in grey underneath, and no status is claimed for roads outside the official set.
- `bus-routes`: the arrival system lists 97 routes and omits seasonal services. The official route page adds them (currently `3AS`, `17S1`, `26S`, `52S`) and they are returned with `live: false`.
- `bus-routes`: the catalog is fetched from DSAT at runtime every 6 hours. A new route appears without a redeploy; the cache keeps the previous list while the refresh runs.
- `bus-routes`: the official `routeChange` flag is set for 50 of 97 routes and the message endpoint answers `routeChange: true` for routes without suspended stops, so the UI no longer badges that flag. Diversions are shown only when `bus-diversion-{routeName}` reports suspended stops.
- `parking`: `data/parking-locations.json` maps the DSAT car park ids to OpenStreetMap `amenity=parking` coordinates (ODbL) by name. `npm run build:parking` regenerates the file from the DSAT list and an Overpass mirror, then falls back to the DSSCU WebMap Carpark POI layer (`https://webmap.gis.gov.mo/arcgis/rest/services/WebMap/MacauMap_P_POI/MapServer/8`, queried with `outSR=4326`) for names OSM does not match. All 92 current car parks have coordinates: 78 from OpenStreetMap and 14 from the Macau GIS layer. The GIS query is build-time only; the runtime reads the checked-in file and makes no GIS request. Occupancy still comes only from DSAT.
- `notices`: the adapter reads the three DSAT lists (特別消息 `emergency.aspx`, 交通改道 `croad.aspx`, 巴士改道 `bus_croad.aspx`) and recovers the location summary that the 特別消息 list hides inside an HTML comment. Incident keywords remain parser categories only. The UI shows these as published arrangements, separate from government RSS news. A selected announcement can match named monitored roads on the map; this does not verify an accident location or whether an event is ongoing. The sources checked in this revision did not establish a complete, reusable live incident feed. See `SOURCE_AUDIT_2026-11-10.md` for the bounded investigation and connection failures.
- `bus-eta-{code}-{direction}`: DSAT publishes no per-stop arrival minutes. The adapter reads the stop each live bus is approaching from `routestation/bus` and the position estimate the same publisher maintains per plate from `busInfoList` in `routestation/location`; the official map page draws these same coordinates. A vehicle without a published position falls back to the coordinates of the stop it is approaching. Positions carry `estimated: true` and never claim to be GPS.
- `bus-eta-{code}-{direction}`: the endpoint `/ddbus/app/passenger/route` is the passenger waiting-time/flow statistics feed behind the official 乘客候車時間 page (half-hour `seg` values, `currentSeg`, `historyRange`, and per-stop `average`/`current` counts). The adapter no longer reads it, and the panel never presents its counts as arrival minutes.
- `bus-eta-{code}-{direction}`: each stop carries `stopsAway`, the number of stops remaining before the next bus reaches it, computed from the approached stop sequences (`routeType: 2` circular routes wrap around the loop). 0 means a bus is heading to that stop. The panel labels 0 as 即將進站 with the plate and shows the remaining count on later stops, matching the official widget's 還有 N 站 count. No minute conversion is made, and stops behind every live bus show a dash on line routes.
- `bus-eta-{code}-{direction}`: the client concatenates the official stop-to-stop segments into one path and glides each marker from its drawn position toward the publisher's newest position estimate at a bounded bus speed, so a coarse step changes distance and direction smoothly and the marker holds when the estimate does not change. Loop routes continue into the next lap. The marker no longer rewinds to the stop just reached when the feed advances.
- `bus-eta-{code}-{direction}`: The official map page draws `route/traffic` as one polyline per stop-to-stop segment. Each returned segment carries `fromStationCode` and `toStationCode`, and its traffic level (1 normal, 2 slow, 3 congested, 4 very congested, -1 unknown) feeds the route line and stop badges. Invalid segments are omitted without shifting later pairings.
- `bus-eta-{code}-{direction}`: The upstream `busType` value is exposed on each vehicle. It is descriptive only; the model does not claim a brand or vehicle type.
- The map ground is flat. The optional 3D view tilts the camera and shows extruded buildings from the OpenFreeMap vector tiles; no terrain elevation source is loaded, so roads stay level.
- Transit models are schematic Blender 5.2 assets, rebuilt from operator photographs and the user's bus-stop reference. `scripts/build-transit-models.py` generates five self-contained GLBs and transparent home-screen button artwork. Buses use operator liveries without a verified plate-to-model mapping. The sign uses stacked cylindrical cabinets; LRT has a platform with a central guideway and a rounded single-carriage mesh instantiated twice. Each carriage follows its own track pose. See `models/REFERENCES.md`. Three.js loads only in 3D; required GLBs load from z14, with LRT carriages available from z12. All kinds use the same fixed 4x world-space schematic display scale. Zoom affects camera projection only; there is no screen-size compensation or high-zoom size cap. Two-car spacing uses the same constant. Landmark overlap is culled with the selected station first. Flat markers remain after model failure. Hidden mobile maps and reduced-motion preferences stop continuous animation.
- Day/night mode recolours the existing OpenFreeMap base layers in the browser. It uses the same style/tile endpoints and leaves application traffic colours unchanged. Precise browser location is used only for straight-line parking distances; it is never included in API or AI requests.
- `assistant`: the server assembles a compact JSON snapshot from the cached normalized contracts (roads with congested, slow, and question-matched segments; bridges; weather; parking; borders; notices; government transport RSS news and source timestamps/stale state; LRT notices; the LRT network with lines, stations, and interchanges) and adds live bus detail when the question names a route or a route is focused in the app: both directions for a single named route, capped at three route-direction slices, each with the full stop list, vehicles, approaching stops, stops-away counts, suspended stops, and per-segment traffic. Snapshot source status includes normalized source ids, retrieval times and stale flags for the bus catalogue and each requested route/direction as well as the general sources. The assistant must identify delayed bus data as the last retrieved estimate. Raw upstream payloads are never forwarded; vehicle positions are the publisher's own estimated coordinates, never presented as GPS, and the prompt forbids converting stops-away counts into minutes. When the question asks whether a route serves a place, the server checks the official stop list and the verified yes or no leads the answer, so the model cannot flip it. Answers can carry a UI action (focus a bus route or an LRT line) that the client applies to the map. The prompt fixes the explanation format, the locale, the snapshot citation, and the no-personal-data rule; `assistantConfigured()` disables the route when `SOURCE_ASSISTANT_ENABLED=false` or `ASSISTANT_API_KEY` is missing. Provider configuration is `ASSISTANT_API_KEY`, `ASSISTANT_BASE_URL`, `ASSISTANT_MODEL`, `ASSISTANT_TIMEOUT_MS`, and `ASSISTANT_RATE_LIMIT_PER_MINUTE`; the key stays server-side. The default provider is DeepSeek; a local OpenAI-compatible server such as Ollama can be used for offline demonstrations.

## Reference material not used

`bus_route/` is local reference material and is not committed (see `.gitignore`).

- `route_list.json` duplicates the live `getRouteAndCompanyList.html` response.
- `routes.json` is text extracted from the official route PDFs. Stop names are garbled by the PDF layout, there is no geometry, and 1 of 91 routes failed to parse, so it is not a reliable source.
- `stops.json` holds official Macau GIS bus-stop coordinates, but the live `routestation/location` endpoint already returns per-route stop coordinates in route order.
- The PDFs are raster route maps, so they cannot provide the official route alignment as coordinates.

## LRT corrections on 2026-11-10

- Track-way assembly now joins shared endpoints at both ends. The previous tail-only greedy algorithm inserted an artificial 1.53 km jump in the checked-in Taipa geometry. Disconnected ways are rejected, not bridged. Terminal overrun beyond the first/last stop is trimmed when the source contains those stop coordinates.
- The fallback was rebuilt from bounded OSM API reads of relations `10402162`, `18238277` and `18361945`. Runtime discovery still uses the existing Overpass endpoints and six-hour shared cache. No new OSM editing-API polling was added. `docs/qa/resident-workspace/lrt-geometry.json` records provenance, counts and the normalized-data hash.
- `stations[].lineCoordinates` is an optional normalized per-line coordinate map. Interchanges retain stable ids and a canonical coordinate while preserving the separate physical stop positions for each line. Selected-line markers, platform models and camera focus use that line's coordinate. Geometry is community-mapped track alignment, not official survey or live vehicle location.
- MLM RSS currently returns two September 2024 notices with `show=false`. The parser now retains both items, honours explicit display flags and interprets publisher CST as UTC+08:00. The legacy `active` field means publisher display status, not verified ongoing disruption. Hidden items are collapsed as history; missing flags do not become active. The assistant receives only displayed notices with publication dates and must not infer ongoing service state.

## Static presentation fonts

The interface uses variable Noto Sans TC via `next/font/google` in the server root layout. Next.js downloads and subsets it at build time, then serves generated font assets from the app origin. There is no browser request to Google Fonts and no new runtime data adapter or source credential. `preload: false` avoids preloading CJK subsets that the visible page does not need.
