## Adapter Notes

- `cameras`: the official catalog repeats some border cameras once per zone under a shared numeric id. The adapter keeps every zoned entry, drops byte-identical repeats, and appends a short deterministic suffix to colliding ids so map features, list keys, and camera selection stay stable.
- `lrt-network`: the server rebuilds the network from OpenStreetMap route relations every 6 hours. Lines are grouped by `ref`; stations are merged by name and proximity under 400 m, so 協和醫院 and 蓮花 stay interchanges. Known stations keep the curated official names and ids from `data/lrt-network.json`; new stations use the OSM name tags. Overpass endpoints are tried in order (`LRT_OVERPASS_URL` overrides them), and failures or a result with fewer than 3 lines or 15 stations fall back to the checked-in file. `npm run build:lrt` refreshes that file with the same builder. The map may show one train per selected line that moves along the official geometry as an explicitly labelled schematic animation at a fixed display speed; it is not live data (ADR 0008).
- `roads`: DSAT publishes live levels for 1,268 monitored segments only. The map draws the full OpenStreetMap street network in grey underneath, and no status is claimed for roads outside the official set.
- `bus-routes`: the arrival system lists 97 routes and omits seasonal services. The official route page adds them (currently `3AS`, `17S1`, `26S`, `52S`) and they are returned with `live: false`.
- `bus-routes`: the catalog is fetched from DSAT at runtime every 6 hours. A new route appears without a redeploy; the cache keeps the previous list while the refresh runs.
- `bus-routes`: the official `routeChange` flag is set for 50 of 97 routes and the message endpoint answers `routeChange: true` for routes without suspended stops, so the UI no longer badges that flag. Diversions are shown only when `bus-diversion-{routeName}` reports suspended stops.
- `parking`: `data/parking-locations.json` maps the DSAT car park ids to OpenStreetMap `amenity=parking` coordinates (ODbL) by name. `npm run build:parking` regenerates the file from the DSAT list and an Overpass mirror, then falls back to the DSSCU WebMap Carpark POI layer (`https://webmap.gis.gov.mo/arcgis/rest/services/WebMap/MacauMap_P_POI/MapServer/8`, queried with `outSR=4326`) for names OSM does not match. All 92 current car parks have coordinates: 78 from OpenStreetMap and 14 from the Macau GIS layer. The GIS query is build-time only; the runtime reads the checked-in file and makes no GIS request. Occupancy still comes only from DSAT.
- `notices`: the adapter reads the three DSAT lists (特別消息 `emergency.aspx`, 交通改道 `croad.aspx`, 巴士改道 `bus_croad.aspx`) and recovers the location summary that the 特別消息 list hides inside an HTML comment. A message whose title or summary contains an incident keyword (意外, 事故, 火警, 水浸, 塌樹, 相撞, 碰撞, 失控, 緊急, and similar) is classified as `incident` and shown in the Alerts tab's first section; planned roadworks, diversions, and events move into a collapsed section. There is no separate official real-time accident API, and the Macau news portals block automated access, so the DSAT lists remain the incident source. The client matches road names in the selected incident against the 1,268 monitored segments and highlights them on the map; an incident that names an unmonitored street has no map position.
- `bus-eta-{code}-{direction}`: DSAT publishes no per-stop arrival minutes. The adapter reads the stop each live bus is approaching from `routestation/bus` and the position estimate the same publisher maintains per plate from `busInfoList` in `routestation/location`; the official map page draws these same coordinates. A vehicle without a published position falls back to the coordinates of the stop it is approaching. Positions carry `estimated: true` and never claim to be GPS.
- `bus-eta-{code}-{direction}`: the endpoint `/ddbus/app/passenger/route` is the passenger waiting-time/flow statistics feed behind the official 乘客候車時間 page (half-hour `seg` values, `currentSeg`, `historyRange`, and per-stop `average`/`current` counts). The adapter no longer reads it, and the panel never presents its counts as arrival minutes.
- `bus-eta-{code}-{direction}`: each stop carries `stopsAway`, the number of stops remaining before the next bus reaches it, computed from the approached stop sequences (`routeType: 2` circular routes wrap around the loop). 0 means a bus is heading to that stop. The panel labels 0 as 即將進站 with the plate and shows the remaining count on later stops, matching the official widget's 還有 N 站 count. No minute conversion is made, and stops behind every live bus show a dash on line routes.
- `bus-eta-{code}-{direction}`: the client concatenates the official stop-to-stop segments into one path and glides each marker from its drawn position toward the publisher's newest position estimate at a bounded bus speed, so a coarse step changes distance and direction smoothly and the marker holds when the estimate does not change. Loop routes continue into the next lap. The marker no longer rewinds to the stop just reached when the feed advances.
- `bus-eta-{code}-{direction}`: The official map page draws `route/traffic` as one polyline per stop-to-stop segment. Each returned segment carries `fromStationCode` and `toStationCode`, and its traffic level (1 normal, 2 slow, 3 congested, 4 very congested, -1 unknown) feeds the route line and stop badges. Invalid segments are omitted without shifting later pairings.
- `bus-eta-{code}-{direction}`: The upstream `busType` value is exposed on each vehicle. It is descriptive only; the model does not claim a brand or vehicle type.
- The map ground is flat. The optional 3D view tilts the camera and shows extruded buildings from the OpenFreeMap vector tiles; no terrain elevation source is loaded, so roads stay level.
- Bus models are generic two-axle Blender 5.2 models. The source is `docs/models/bus-models.blend`; runtime exports are `public/models/bus-tcm.glb` and `public/models/bus-transmac.glb`. MapLibre renders them in a custom WebGL layer from z17 at a 1.8x display scale so they stay readable at street zoom, then keeps a fixed on-screen size above z19. Lower zooms use a livery-coloured marker and plate label. The layer-menu mode control switches the whole map to 2D: the camera flattens, buildings hide, the GLB layer does not load, and the enlarged flat marker with its plate label stays visible at every zoom. The UI states that the bus model is generic, not brand-specific.
- `assistant`: the server assembles a compact JSON snapshot from the cached normalized contracts (roads with congested, slow, and question-matched segments; bridges; weather; parking; borders; notices; LRT notices; the LRT network with lines, stations, and interchanges) and adds live bus detail when the question names a route or a route is focused in the app: both directions for a single named route, capped at three route-direction slices, each with the full stop list, vehicles, approaching stops, stops-away counts, suspended stops, and per-segment traffic. Raw upstream payloads are never forwarded; vehicle positions are the publisher's own estimated coordinates, never presented as GPS, and the prompt forbids converting stops-away counts into minutes. When the question asks whether a route serves a place, the server checks the official stop list and the verified yes or no leads the answer, so the model cannot flip it. Answers can carry a UI action (focus a bus route or an LRT line) that the client applies to the map. The prompt fixes the explanation format, the locale, the snapshot citation, and the no-personal-data rule; `assistantConfigured()` disables the route when `SOURCE_ASSISTANT_ENABLED=false` or `ASSISTANT_API_KEY` is missing. Provider configuration is `ASSISTANT_API_KEY`, `ASSISTANT_BASE_URL`, `ASSISTANT_MODEL`, `ASSISTANT_TIMEOUT_MS`, and `ASSISTANT_RATE_LIMIT_PER_MINUTE`; the key stays server-side. The default provider is DeepSeek; a local OpenAI-compatible server such as Ollama can be used for offline demonstrations.

## Reference Material Not Used

`bus_route/` is local reference material and is not committed (see `.gitignore`).

- `route_list.json` duplicates the live `getRouteAndCompanyList.html` response.
- `routes.json` is text extracted from the official route PDFs. Stop names are garbled by the PDF layout, there is no geometry, and 1 of 91 routes failed to parse, so it is not a reliable source.
- `stops.json` holds official Macau GIS bus-stop coordinates, but the live `routestation/location` endpoint already returns per-route stop coordinates in route order.
- The PDFs are raster route maps, so they cannot provide the official route alignment as coordinates.
