## Architecture

- `src/server/sources/` owns all external payload parsing and normalization.
- `src/server/cache.ts` owns shared TTL cache, stale fallback, source locks, circuit state, and rate limiting.
- `src/server/sources/assistant-journeys.ts` owns model destination extraction and JSON journey selection through the existing shared routing/cache functions. See ADR 0017.
- `src/server/sources/assistant.ts` owns the traffic-question assistant: it builds a compact snapshot from the cached normalized sources and calls an OpenAI-compatible chat completions endpoint. See ADR 0007.
- `src/app/api/v1/` exposes the public read-only API.
- `src/components/` owns the resident workspace, map presentation, local favourites and client polling.
- `data/lrt-network.json` is generated from OpenStreetMap route relations and official LRT station names.
- The LRT network is rebuilt from OpenStreetMap at runtime every 6 hours. The checked-in JSON is the fallback and supplies official names for stations it already knows. See ADR 0006.

External data never enters a client component directly. Public contracts are defined in `src/lib/contracts.ts`.

## Known Risks

- A local server-side AI key was present on 2026-11-13 (its value was not logged). Common destination requests use local routing and work without the provider. A live local `deepseek-chat` call returned dated traffic announcements on November 13. Publication times are now serialized in UTC+08:00 before provider calls.
- The DSAT Node certificate-chain failure was reproduced and fixed locally on 2026-11-13 with an exact-origin public intermediate, retaining TLS verification (ADR 0015). News and arrangements now load and poll every minute. Production availability must still be checked after deployment.
- RSS publication lag and finite item windows remain unknown; the app cannot promise incident completeness or ongoing-event status.
- Native mobile applications and physical-device frame-rate/battery measurements are outside this web revision. Chromium touch emulation is not a physical iOS Safari test.
- DSAT dynamic endpoints are used by official web applications but are not all formally documented. Response fields can change without notice.
- The Public Security Police border status endpoint is used by its official mobile pages but is not a documented public API. It may change or block server requests; border data remains optional and other modules must continue to work.
- OpenFreeMap and camera HLS availability are external runtime dependencies.
- Extruded buildings depend on OpenFreeMap vector tiles; the ground is flat because no terrain elevation source is loaded.
- The 3D bus layer needs WebGL2 and successful GLB loading. If either fails, the 2D marker and plate label remain, but the 3D model does not render.
- The LRT network refresh depends on the Overpass API. Outages or incomplete results fall back to the checked-in network; new lines and stations can carry OSM names instead of official MLM names.
- DSAT `busType` values are exposed in the public payload but are not mapped to specific vehicle brands or models because no documented mapping exists.
- Only the 1,268 segments DSAT publishes carry congestion status. Grey roads mean no official live data, not clear traffic.
- Render Key Value is private to the workspace. Local development falls back to a process-memory cache.
- The AI assistant depends on an external LLM provider and a funded API key. The grounding context limits but cannot eliminate model errors, and the same question can produce different wording between calls.

## Journey and map revision, 2026-11-10

- The bus tab has an origin/destination planner. Origin accepts the device location or an official stop; destination accepts an official stop name/code. Current location stays in browser memory. Coordinate endpoints consider all platforms within 500 m. Manually selected stations keep their exact platform by default. The nearby-stop checkbox explicitly includes other platforms within 500 m; the pure planner also defaults to exact codes. Direct and one-transfer plans use published directional stop order; transfer requires the same exact stop code, and no continuation past a terminus is inferred. Sorting is ridden stop edges, straight-line access distance, then transfers. No fastest-route, fare, walking-path or travel-minute claim is made. Each numbered option groups its legs and shows boarding/alighting codes, per-leg counts, circular-line labels and unverified service hours.
- The dated DSAT topology snapshot has 90 routes, 111 directions, 2,826 stop occurrences and 599 distinct stop codes, collected at 2026-11-10T11:51:19.223Z. `/api/v1/bus/network` uses the shared cache; `npm run build:bus-network` explicitly refreshes the checked-in snapshot with four concurrent official requests. It is not a live service-availability feed. Failed/incomplete builds preserve the previous file. See ADR 0012 and `docs/qa/resident-workspace/bus-network-verification.json`.
- Results keep their search fields when opening live bus details. A network-edition or location change invalidates old results. The boarding shortcut only selects a uniquely matching current stop, and newer navigation clears pending selection intent.
- Whole-journey maps fetch at most two existing route/direction ETA APIs while the bus journey is visible. A pure geometry builder matches contiguous official segments to each dated leg and stop count. Missing/ambiguous shapes or inconsistent interchange coordinates are omitted with a warning. The map uses separate leg colours and boarding/transfer/alighting markers; the list has the same ordered steps. Checking one leg's live arrivals and returning preserves the complete journey. Stable polling preserves map pan.
- Walking access/egress lines are explicitly straight-line connectors. An ordinary, user-opened Google Maps walking link shares only that leg's origin/destination after clicking; there is no automatic Google request or API-key integration. The page discloses this before the link is used. A new location search clears the selected journey. Decorative dark navigation no longer uses a white inset highlight; keyboard focus remains visible.
- Three-dimensional bus signs are offset perpendicular to the official path using bus/sign footprints and bend checks. A leader connects each display sign to its official stop anchor. Vehicles and official anchors do not move. The fixed 4× world scale is unchanged. Tight locations without a collision-free placement retain the flat stop marker.
- `/api/v1/lrt/service` reads current MLM service hours and 17 official timetable links. The September 2026 publisher edition remains visible. These are schedules; no verified public live-train position or arrival endpoint was established in the bounded audit. Existing schematic train animation stays labelled. See `LRT_DATA_AUDIT_2026-11-10.md`.
