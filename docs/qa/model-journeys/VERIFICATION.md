## Live model and data checks

The configured model resolved “我想去澳門體育館” to 澳門東亞運動會體育館 in about 1.5 seconds. An initial real-data check found a disconnected pedestrian component at the venue: the point could snap to an internal path, but no nearby bus stop had a mapped path to it. The adapter now preserves nearby bus options with labelled straight-line access for such endpoints, without drawing invented walking geometry.

Using public Senado Square coordinates as a synthetic origin, the model returned three validated options in about 4.9 seconds. `live-destination.json` and `live-plans.json` contain the normalized results. These coordinates are a test landmark, not the user's location.

A final live Chrome submission “由議事亭前地去澳門體育館” displayed three model-ranked options, selected the recommended 21A/25B journey and showed both bus legs plus mapped access and the explicitly straight-line final connection. `live-model-plans.jpg` records the real model output. Browser-location success/denial was tested using controlled geolocation fixtures, not the user's actual location.

## Limits

The planner searches direct buses, one transfer and mapped walking paths. It uses dated topology, reviewed terminal service windows where available and the existing suspension feed. It does not provide verified arrival minutes, pedestrian closures or guaranteed current service for routes without reviewed hours. Missing/stale suspension checks are labelled. Model explanations are generated from the provided evidence; route IDs, stop sequences and geometry are supplied by the server, not generated by the model.

## Vehicle status revalidation fix (2026-11-13)

A deliberate live read of route 21A sampled eight responses at two-second intervals. Every response contained four feed-position vehicles and 37 route segments. The cache `stale` flag alternated between true and false, with payload ages around 0–3.8 seconds. The journey UI incorrectly removed vehicles whenever that flag was true.

The map and detail panel now use the existing shared age check (two-second bus TTL plus eight-second grace). A background refresh preserves the vehicle list and an opened details element. Read errors or genuinely old data still stop showing current positions. Poll frequency and server caching are unchanged.

The new browser regression failed before the fix when both vehicle details disappeared. After the fix it passes on desktop and mobile through repeated fresh/revalidating transitions, preserves the expanded list, then correctly removes current positions for a 20-second-old snapshot. All 18 journey-map/AI browser checks and all 153 unit tests pass; typecheck, lint, build and documentation checks pass. The rebuilt local standalone service was restarted on port 3100.
